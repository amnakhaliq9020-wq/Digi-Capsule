4. Task 1 — Contacts Page (Start Here)
Goal: Login ke baad user apne recipients manage kar sake. Screen lightweight, clear aur responsive ho.
UI: Page title "My Contacts", Add Contact button, contacts list/table, edit/delete actions.
Form fields: Name (required), Email (valid format), Phone (country code supported). At least one usable delivery channel should be required; final rule Zamin se agree karein.
Actions: Add -> save -> new contact list mein nazar aaye; Edit -> previous data pre-fill; Delete -> confirmation dialog -> list update.
States: empty list, form errors, save loading, save failure, success feedback. Mobile par table ko stacked contact cards mein convert karein.
Mock data se development start karein. Zamin approval ke baad user-scoped API integration karein.

5. Task 2 — Home Dashboard
Goal: User ko ek glance mein check-in aur saved records ka status samajh aaye. Amna sirf values display karegi; schedule calculate karna Zamin ki service ki responsibility hai.
Top summary: "Last I’m Alive" date/time and "Next check-in due" date/time (backend supplied).
Memories list: title, type, chosen recipients and rule label (On this date / If I am gone).
Contacts list: name and preferred contact details, with shortcut to Contacts.
Clear empty states, loading indicator, error/retry experience, mobile responsive layout.
I’m Alive button ka actual check-in action Zamin own karega; Dashboard sirf placement ya navigation space provide kar sakta hai.

7. Integration & Ownership Rules
Amna initially builds frontend against mock data / agreed API types.
Before connecting any page: send Zamin screen link, required endpoints, field names and test cases; request explicit approval.
Zamin supplies authentication context and secure endpoints. Amna must not store secret API keys in frontend code.
Contacts create/edit/delete must be scoped to the logged-in user. Memories and dashboard data must be accessed only through authorized APIs.
All warning templates pass placeholder review, readability review and final sign-off before Zamin schedules sends.
8. Final Handoff Checklist
Contacts CRUD works for two recipients, with validation and mobile layout.
Dashboard shows last check-in, next due, memory list, contacts list and empty/loading/error states.
Three email + three SMS warning templates are final and approved.
All UI integration done only with Zamin approval; unresolved APIs documented.
Smoke test: pressing I’m Alive delivers nothing; delayed "if gone" logic and scheduled video delivery tested by Zamin in staging (accelerated test clock, no real customer messages).
